任务: 从材料中提取所有形如「名称 = 数值 单位」的指标，并以 JSON 输出，键为 name、value、unit。

材料:
3.1 静态曲线 | 原 bench 条件下的吞吐和显存记录 | 用作本项目路线排名时，必须在统一 server 协议下重测；CPU/GPU 计算归属需补证 |
| 3.2 贴顶崩塌 | 稳定退化现象及原始方差 | “已证明物理原因”“1600 MiB 通用阈值”“只可能发生在cache0”均证据不足 |
| 3.3 V 型 | nc20、原负载下的实测值 | 1100–1200 MiB 不能当通用阈值；应重测零点邻域及冷暖/题材依赖 |
| 3.4 缓存上限 | 五种联合配置的历史成绩 | **必须撤回缓存单因素单调提升/未饱和的推论**，因为 ncmoe 同时变化 |
| 3.5 TTFT/长上下文 | 定义和请求日志可追溯的原始时间 | 若 TTFT 实为 `prompt_ms`，TTFT 标签作废；cache、KV或ctx混变时，斜率与衰减率须重测 |
| 3.6 CPU 时间 | 同一测量窗口的 CPU 秒和墙钟原始值 | “CPU零专家计算”须通过执行位置判决；若总CPU秒除以decode时间，平均核数必须重算 |
| 硬件与内存带宽 | 本次提供的实测环境基线 | 无需因执行模式问题重测；40.5 GB/s不能直接作为MoE专家有效带宽 |

| 路线 | 可测胜出条件 | 边界怎样得到 |
|---|---|---|
| A | CPU 专家路径的端到端时间小于 B；或在目标显存预算下，B 的缓存/搬运开销使其退化 | 固定负载，扫描 B 容量；把 A/B 差值对专家 miss MiB/token 作图，记录交叉区间 |
